## 2. 검증 방법 (P2) — DB 없이 재현

테스트가 **별도 DB에 연결된 서비스**에서 수행되어 크롤 DB 직접 조회로는 판정할 수 없다.
대신 실패 URL을 **라이브로 fetch해 저장소의 실제 파이프라인 코드를 그대로 태웠다.**
DB가 무엇이든 파이프라인 코드는 동일하므로 "수집 가능한가 / 무엇이 저장되는가"는 독립 판정된다.

사용 모듈(전부 기존 코드, 신규 로직 없음):
`crawl.url_normalize` → `clean.extractor.extract` → `clean.date_extract` →
`crawl.board.classify_freshness` → `refine.pre_rules.check` →
`quality.scorer.score_document` → `quality.embedding_policy.resolve_embedding_targets`

품질 채점은 refine 결과(summary/keywords)가 **정상이라고 가정한 낙관적 상한**으로 계산했다.
그 조건에서도 Q1이 아니면 게이트 탈락이 확정된다(보수적 판정).

### 4-0. ✅ 검색 임베딩 — **배제됨** (2026-08-21 확인)

**결론 먼저**: KSPO 네임스페이스의 `embedding`은 **`text-embedding-3-large`**로 확인됐다(사용자 실측).

이로써 다음이 따라 나온다:

1. **KSPO는 Strategy B로 자체 컬렉션에 분리돼 있다.** 공유 컬렉션 `tiledesk-llm`(1536d)이 아니라

   **(a) 해당 문서가 KB/색인에 없음**, **(b) 검색 파라미터(top_k=4·hybrid=False·reranking=False)** 둘이다.
3. **새 가설 — 재인제스트 누락.** 마이그레이션은 KB **4,112건 전체를 앱을 통해 재인제스트**하는

   `kb.status`가 갱신되지 않은 채 남는다. 절차서 자체가

### 4-1. 🔴 `<main>` 유무가 표 보존을 가른다 — 가장 파급이 큰 결함

`clean/extractor.py:84-93`의 1순위 `_try_main_article`은 `node.text(separator="\n")`로
텍스트를 뽑는다. `<main>`이 200자만 넘으면 여기서 확정되므로,
`include_tables=True`가 걸린 trafilatura(100행)는 **표 페이지에서 아예 실행되지 않는다.**

**실측 대비 — 같은 파이프라인, 정반대 결과:**

`www.kspo.or.kr` (`<main>` 존재 → `main_article`) — 기금수입운용상황:
```

예탁이자수입
37,665,000,000
0
0
16,462,655,020
```
→ 값은 있지만 **어느 열이 "누계수납금액"인지 알 방법이 없다.** 열 머리글은 표 맨 위에 따로 나열됨.

`www.ecolian.or.kr` (`<main>` 없음 → `trafilatura`) — 예약안내:

|---|---|---|
| 벌점기준 | ㅇ 2일전취소 15점 ㅇ 1일전취소 25점 ㅇ 당일취소/노쇼 40점 … |

→ **마크다운 파이프 표로 행/열이 완전히 보존된다.**

같은 페이지·같은 형식인데 **행 길이에 따라 성패가 갈린다** — 구조 손실의 전형적 지문이다.
