## 본 문서 사용법

본 시스템은 KSPO 공개 콘텐츠를 자동 수집·정제·임베딩하여 Tiledesk 챗봇용 Qdrant에 적재하는 내부 도구다. 무한아이티가 PRD를 작성하면서 외부 부서 결정이 필요한 10개 항목에 대해 **잠정안**을 명시했고, 본 문서로 부서별 확인·회신을 요청한다.

각 항목은 **"잠정안 그대로 진행 / 변경 (어떻게)"** 두 가지 답으로 회신 가능하다. 부서별 송부 시 본 문서에서 해당 부서 섹션만 발췌해 전달한다.

응답 형식: 항목 번호 + "수용" 또는 "수정 — <상세>" + 결정자 + 일자.

## KSPO IT 인프라팀

### Q1. 프록시 host:port 실값

**배경**: 본 시스템은 OpenAI API(`api.openai.com`)에 outbound 호출이 필요하며, KSPO 망분리 환경에서는 사내 프록시 경유가 필수다. 메커니즘은 PRD round 2에서 확정됨 (`HTTPS_PROXY` 표준 환경변수, anonymous, CONNECT 중계만, `api.openai.com` 화이트리스트).

**잠정안**:
- `.env.example`에는 placeholder
- 운영 시 KSPO 인프라팀이 실제 host:port 값을 `.env`에 입력 (`http://<host>:<port>` 형식)

**요청 사항**:
- [ ] 프록시 호스트:포트 실값 — `http://_______:____`
- [ ] 인증 방식 — 인증 없음 / 사내 ID-PWD / 기타: ___
- [ ] 화이트리스트 등록 — `api.openai.com` 추가 가능 여부 ✔ / ✘
- [ ] TLS 인스펙션 — 없음(CONNECT) / 있음(사내 root CA 마운트 필요) ___
- [ ] M2 시작 전 (refine·embed 호출 시작 전) 실값 회신 가능 여부 ✔ / ✘

**미확정 시 영향**: M2 (Crawl + Refine 파이프라인) 진행 차단 — refine 호출이 사내망에서 outbound 못 함.

## KSPO IT 자산팀

### Q4. 호스트 도입 방식

**배경**: 본 시스템은 사내 IDC 단일 호스트 가정(`docs/prd/05_nfr_infra.md` §6.1). 권장 최소 사양: 8 vCPU / 16 GB RAM / 200 GB SSD.

**잠정안**:
- 권장: 기존 KSPO IDC 호스트 1대 활용 (사양 충족 시)
- 미충족 시: 신규 VM 1대 할당

**요청 사항**:
- [ ] 기존 호스트 활용 가능 여부 — 호스트명/IP `___________________`
- [ ] 사양 충족 여부 (CPU / RAM / SSD) 회신
- [ ] 미충족 시 신규 VM 일정 — 도입 예상일 `__________`
- [ ] 사내망 연결 방식 (VLAN, 방화벽 정책) 회신

**미확정 시 영향**: M0 시작 차단 — 어디에 배포할지 결정 안 됨.

## KSPO IT 보안팀

### Q3. 백업 미운영 정책 허용 여부

**배경**: 본 시스템 source of truth는 원천 사이트(KSPO 공개 페이지). 손실 시 재크롤·재정제·재임베딩으로 복원 가능. RTO 7일 이내, RPO 최대 7일 (`docs/prd/05_nfr_infra.md` §5.4).

**잠정안**: 백업 미운영. Fallback SOP 준비됨 (KSPO NAS rsync — KSPO IT 정책상 요구 시 적용).

**요청 사항**:
- [ ] 백업 미운영 정책 수용 ✔ / ✘
- [ ] ✘ 시 — Fallback SOP 적용 (`storage/raw,refined,attachments` 일일 rsync to KSPO NAS) ✔ / ✘
- [ ] NAS 마운트 경로 / rsync 대상 경로 회신

### Q5. TLS 종료 위치

**배경**: 본 시스템은 nginx 컨테이너로 host 80/443 노출 (`docs/prd/05_nfr_infra.md` §6.3, §6.4).

**잠정안**: nginx 컨테이너에서 종료 (사내 인증서 마운트).

**요청 사항**:
- [ ] nginx 컨테이너 TLS 종료 수용 ✔ / ✘
- [ ] ✘ 시 — 외부 LB(예: F5)에서 종료, nginx는 HTTP만 ✔ / ✘
- [ ] 사내 인증서 발급 절차 / 갱신 주기

### Q6. 이미지 레지스트리

**배경**: 망분리 환경에서 Docker Hub 직접 풀 불가 가정. M0.T0.2(Docker Compose)에서 결정 필요.

**잠정안**:
- 사내 레지스트리 우선 (Harbor / GitLab Container Registry)
- 미보유 시 로컬 빌드 + `docker save` tar 배포

**요청 사항**:
- [ ] 사내 레지스트리 보유 여부 ✔ / ✘
- [ ] ✔ 시 — 호스트명 / 인증 방식 / 푸시 권한 회신
- [ ] ✘ 시 — 로컬 빌드 + `docker save` tar 배포 절차 수용 ✔ / ✘

### Q7. CSAP / ISMS-P 대상 여부

**배경**: 본 시스템은 공개자료만 다루는 내부 도구. 단일 Admin 운영. 외부 노출 없음(사내망 only). PII 자동 마스킹 미운영(Admin 수동 제거 정책).

**잠정안**: 비대상 가정.

**요청 사항**:
- [ ] CSAP / ISMS-P 대상 여부 — 비대상 ✔ / 대상 ✘
- [ ] 대상 시 — 추가 요구사항(접근로그·암호화 등) 회신

## KSPO 운영기획팀

### Q10. KSPO 기존 FAQ 메뉴 유지 여부 (챗봇 도입 후)

**배경**: 본 시스템은 KSPO 공개 콘텐츠를 챗봇용 KB로 적재한다. KSPO 메인사이트는 기존 FAQ 메뉴를 운영 중이며, 챗봇 도입 후 FAQ를 어떻게 할지 결정 필요 (PRD `docs/prd/02_overview.md` §1.3).

**잠정안**: 챗봇 도입 후에도 FAQ 메뉴는 별도로 유지.

**요청 사항**:
- [ ] FAQ 메뉴 유지 ✔ / 폐지 ✘ / 챗봇으로 통합 ✘
- [ ] 폐지 시 — FAQ 콘텐츠를 본 시스템 KB로 이관할지 ✔ / ✘
- [ ] 통합 시 — Tiledesk 챗봇 위젯에 "FAQ" 카테고리 노출 요구 여부 ✔ / ✘

**미확정 시 영향**: 사용자 경험 단절 가능성 — 챗봇 안내·FAQ 안내 중복 시 혼란.
