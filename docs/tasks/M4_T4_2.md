## Spec

### `POST /api/jobs/refresh-url`

요청:
```json
{
  "url": "https://www.kspo.or.kr/bbs/view.do?bbsId=N1&nttId=12345",
  "force": false
}
```

- `url`: 필수. URL 정규화(T2.1) 후 url_hash로 페이지 조회
- `force`: 선택, 기본 false. true면 content_hash 비교 skip — 무조건 refine 재실행

응답: 201 + `{job_id, page_id, arq_job_id}`

```python
class RefreshUrlRequest(BaseModel):
    url: str = Field(min_length=10, max_length=2000)
    force: bool = False

    @field_validator("url")
    @classmethod
    def must_be_http(cls, v: str) -> str:
        if not v.startswith(("http://", "https://")):
            raise ValueError("url must start with http:// or https://")
        return v


@router.post("/refresh-url", response_model=RefreshUrlOut, status_code=201,
             dependencies=[Depends(rate_limit_60_per_minute)])
async def refresh_url(body: RefreshUrlRequest, s: AsyncSession = SessionDep, _admin=AdminDep):
    normalized, url_hash = normalize_url(body.url)
    page = (await s.execute(
        select(Page).where(Page.url_hash == url_hash)
    )).scalar_one_or_none()
    if page is None:
        raise HTTPException(404, "page not found — register the domain and run full first")

    job = CrawlJob(
        domain_id=page.domain_id, job_type="url_refresh", status="PENDING",
        seed_urls=[normalized], stats={"discovered": 0, "fetched": 0, "skipped": 0, "refined": 0,
                                       "indexed": 0, "dropped": 0, "errors": 0, "removed": 0},
    )
    s.add(job); await s.commit(); await s.refresh(job)

    pool = await get_arq_pool()
    arq_job = await pool.enqueue_job(
        "refresh_url", job_id=job.id, page_id=page.id, force=body.force,
    )
    job.arq_job_id = arq_job.job_id
    await s.commit()
    return {"job_id": job.id, "page_id": page.id, "arq_job_id": arq_job.job_id}
```

### `refresh_url` ARQ task

```python
async def refresh_url(ctx, *, job_id: int, page_id: int, force: bool) -> None:
    """단건 URL을 fetch → clean → (force 또는 변경) refine → embed → Qdrant.

    구현은 fetch_page+clean_page+refine_page 체인을 단건으로 압축:
    - frontier 사용 안 함 (BFS 미진입)
    - extract_links 호출 안 함 (단건만)
    - force=True면 clean_page의 content_hash 비교 분기를 건너뛰고 refine_page 진입
    """
    s = ctx["session_factory"]()
    if await is_cancelled(s, job_id): return

    page = await s.get(Page, page_id)
    domain = await s.get(Domain, page.domain_id)

    await ctx["rate_limit"].acquire_token(domain.host, float(domain.rate_limit_rps))

    try:
        result = await ctx["fetcher"].fetch(page.url, user_agent=domain.user_agent or settings.crawl_user_agent_default)
    except Exception as e:
        await mark_error(s, page_id, error=str(e))
        await finish_job(s, job_id, status="FAILED", error=str(e))
        return

    if result.http_status == 404:
        await handle_404(s, page_id, job_id)
        await finish_job(s, job_id, status="SUCCESS")
        return

    # 다음 단계는 force 플래그를 반영해 직접 호출
    await save_raw(...); await mark_fetched(s, page_id, ...)
    extraction = extract(result.raw_bytes, result.content_type, blacklist=...)
    new_hash = normalize_for_hash(extraction.body_text)

    if not force and page.content_hash == new_hash:
        page.last_fetched_at = datetime.now(timezone.utc)
        await bump_stats(s, job_id, skipped=1, fetched=1)
        await finish_job(s, job_id, status="SUCCESS")
        return

    # refine + chunk + embed + Qdrant (T4.1 refine_page 핵심 로직 재사용 — 함수로 분리해 호출)
    await _refine_chunk_embed_upsert(s, ctx, job_id, page, extraction, new_hash)
    await finish_job(s, job_id, status="SUCCESS")
```

> **함수 분리**: `refine_page`의 핵심 부분을 `_refine_chunk_embed_upsert(s, ctx, job_id, page, extraction, new_hash)` 헬퍼로 추출 — `refresh_url`과 `refine_page`가 공유. 본 Task에서 `tasks/pipeline/refine_page.py` 리팩토링 포함.

### `POST /api/jobs/{id}/cancel`

```python
@router.post("/{id}/cancel", status_code=204)
async def cancel_job(id: int, s: AsyncSession = SessionDep, _admin=AdminDep):
    job = await s.get(CrawlJob, id)
    if job is None:
        raise HTTPException(404)
    if job.status not in ("PENDING", "RUNNING"):
        raise HTTPException(409, f"job is already {job.status}")
    job.status = "CANCELLED"
    job.finished_at = datetime.now(timezone.utc)
    await s.commit()
    return Response(status_code=204)
```

> ARQ worker는 매 task 시작 시 `is_cancelled(job_id)` 체크 → True면 즉시 종료 (T2.4에서 정의). RUNNING task는 자연스럽게 완료까지 진행, 다음 task는 진입 전 종료 — KSPO 운영자 기대 부합.

### Rate Limit (`api/rate_limit.py`)

Redis 슬라이딩 윈도우 (`refresh_url` 분당 60회 — 도메인 단위가 아닌 **전역**, 단일 Admin 가정).

```python
async def rate_limit_60_per_minute(request: Request) -> None:
    """FastAPI 의존성. Redis ZSET의 슬라이딩 윈도우.

    key: rate_limit:refresh_url
    score = unix_ms timestamp
    member = uuid4 hex (per-call uniqueness)

    1. ZREMRANGEBYSCORE key 0 (now - 60_000)        — 윈도우 밖 제거
    2. ZCARD key                                     — 현재 윈도우 호출 수
    3. >= 60: 429 Too Many Requests + Retry-After: 60
    4. ZADD + EXPIRE 65s
    """
    redis = await get_redis()
    now_ms = int(time.time() * 1000)
    key = "rate_limit:refresh_url"
    pipe = redis.pipeline()
    pipe.zremrangebyscore(key, 0, now_ms - 60_000)
    pipe.zcard(key)
    _, count = await pipe.execute()
    if count >= 60:
        raise HTTPException(429, "rate_limit_exceeded", headers={"Retry-After": "60"})
    await redis.zadd(key, {uuid.uuid4().hex: now_ms})
    await redis.expire(key, 65)
```

> 다른 엔드포인트(`/api/jobs/full/{id}`, `/incremental/{id}`)에는 적용 안 함 — full/incremental은 Admin이 명시적으로 트리거하는 무거운 작업이라 폭주 위험 낮음. `/refresh-url`만 사용자 액션 패턴(Page 상세에서 "Force Refresh" 버튼)에 노출되어 폭주 가능성.

### 테스트

`test_refresh_url.py` (≥8):
- `force=false` + 변경 없음 → status SUCCESS + skipped=1 + LLM 미호출
- `force=true` + 변경 없음 → SUCCESS + refined=1 + LLM 호출됨
- `force=false` + 변경 있음 → SUCCESS + refined=1
- 등록되지 않은 URL → 404
- URL 정규화 후 매칭: `?utm_source=x` 차이만 있는 URL → 동일 페이지로 매칭
- 404 응답 → handle_404 호출 + Job SUCCESS (URL이 사라진 정상 결과)
- 응답 5xx → fetcher 재시도 5회 후 Job FAILED
- URL 검증: `javascript:alert(1)` → 422

`test_job_cancel.py` (≥6):
- PENDING Job 취소 → CANCELLED + finished_at 설정
- RUNNING Job 취소 → CANCELLED, 다음 ARQ task 진입 시 종료 검증
- 이미 SUCCESS인 Job 취소 → 409
- 이미 FAILED인 Job 취소 → 409
- 존재하지 않는 Job → 404
- 취소된 Job의 stats는 보존됨

`test_api_rate_limit.py` (≥4, fakeredis):
- 1~60회 호출 → 200 OK
- 61회 → 429 + `Retry-After: 60`
- 60초 경과 후 재호출 → 200 OK
- 다른 엔드포인트(`/api/domains`)는 영향 없음
