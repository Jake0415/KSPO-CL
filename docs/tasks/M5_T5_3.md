### `01_admin_workflow.md` (Admin 일과)

```markdown
# Admin 일과

## 매일 (5분)
- Admin UI `/` 대시보드에서 활성 Job 확인
- 알림 배너 — 80% 도달 또는 ERROR
- 최근 에러 5건 검토 — `crawl_jobs.status=FAILED` 있으면 런북 참조

## 매주 일요일 03:00 KST 후 (10분)
- weekly cron이 실행한 incremental Job 결과 확인
- 도메인별 stats(skipped/refined/indexed/errors) 요약 검토
- 새로 ERROR 상태가 된 페이지 스팟 체크

## 도메인 추가 (이벤트 발생 시)
1. `/domains/new` 폼 입력
2. 저장 후 `POST /api/jobs/full/{id}` 자동 트리거
3. 1~3시간 후 INDEXED 페이지 수 확인

## 페이지 강제 재크롤 (이벤트 발생 시)
- `/pages/{id}` 상세 → "Force Refresh" → `POST /api/jobs/refresh-url`

## PII 노출 발견 시
1. `/domains/{id}` → deny_patterns에 해당 URL 패턴 추가
2. 페이지 상세 → 즉시 삭제 버튼 (Tier 2 — 현 v2.1은 SQL DELETE 또는 도메인 비활성화 후 재활성화)
```

### `03_troubleshooting.md`

런북 A/B/C 미해당 자주 발생 문제:

```markdown
# 자주 발생하는 문제

## Q1: Job이 PENDING 상태에서 진전이 없음
**원인 후보**: worker 미가동 / Redis 연결 실패
**진단**: `docker compose ps worker`, `docker compose logs worker --tail=50`
**조치**: `docker compose restart worker`. 지속되면 Redis 헬스 확인

## Q2: 페이지 본문이 추출 안 됨 (DROPPED 'too_short')
**원인 후보**: 동적 페이지(JS 렌더링) — Trafilatura가 콘텐츠 못 잡음
**진단**: `pages.storage_paths`로 raw HTML 확인
**조치**: 도메인 설정에서 `use_playwright=true` (Tier 2 — 현 v2.1은 미지원)

## Q3: 첨부 다운로드 실패
**원인 후보**: 100MB 초과 / 사이트 인증 필요
**진단**: `attachments.extraction_status`, worker 로그 'AttachmentTooLarge'
**조치**: 100MB 초과는 정책상 미지원. 인증 필요 시 공개 자료 가정 위반 — 도메인 등록 검토

## Q4: 검색 품질이 낮다 (Tiledesk 측 보고)
**원인 후보**: 청크 토큰 수 과다 / 헤더 컨텍스트 부족 / 카테고리 필터 부재
**조치**:
1. `chunks.token_len` 분포 확인
2. 청크 헤더 출력 검토 — `summary` 필드가 잘 채워졌는지
3. 카테고리 필터는 Tier 2 — 운영 측정 후 도입 검토

## Q5: 디스크 사용량 급증
**원인 후보**: storage/raw + attachments 영구 보관 정책
**조치**: 본 시스템 백업 미운영 — KSPO IT 정책상 디스크 한계 도달 시
   1) `docs/prd/05_nfr_infra.md` §5.4 Fallback SOP 검토
   2) 단기: 도메인별 storage 압축 (Tier 2)
   3) 장기: KSPO NAS rsync 보강 (`storage/` 외부 보관)
```

### PDF 빌드 (`scripts/build_pdf.sh`)

```bash
#!/usr/bin/env bash
# 운영 매뉴얼 PDF 빌드 — pandoc + wkhtmltopdf 또는 weasyprint
set -euo pipefail

OUT=dist/kspo-ingest_운영매뉴얼_v2.1.pdf
mkdir -p dist

# 1) 본문 합치기 (개별 .md → 단일 .md)
COMBINED=dist/_combined.md
{
  echo "% KSPO 적재 시스템 운영 매뉴얼"
  echo "% v2.1 / 2026-05-07"
  echo
  cat docs/design/00_overview.md
  cat docs/operations/01_admin_workflow.md
  cat docs/operations/02_kspo_it_workflow.md
  cat docs/runbook/A_kb_dim_mismatch.md
  cat docs/runbook/B_openai_failure.md
  cat docs/runbook/C_tiledesk_down.md
  cat docs/operations/03_troubleshooting.md
  cat docs/operations/04_handover_checklist.md
  echo
  echo "## 부록 A — 환경변수 일람"
  echo '```'
  cat .env.example
  echo '```'
} > "$COMBINED"

# 2) PDF 생성
pandoc "$COMBINED" \
  --toc --toc-depth=2 \
  --pdf-engine=xelatex \
  -V mainfont="Noto Sans CJK KR" \
  -V geometry:margin=2cm \
  -V documentclass=article \
  -o "$OUT"

echo "✓ $OUT 생성 완료 ($(du -h "$OUT" | cut -f1))"
```

> **Windows 호환**: KSPO 운영 환경이 Linux 호스트지만 무한아이티 개발자가 Windows일 수 있음. 본 스크립트는 WSL/Linux/macOS 가정. Windows 직접 빌드는 `pandoc.exe + miktex` 권장 (별도 가이드).

`scripts/build_training_pdf.sh`도 유사 — `marp-cli`로 슬라이드 → PDF.

clean:

```
