# M4.T4.1 — Incremental Job (content_hash 비교 + Orphan 처리)

## Goal

`incremental` Job 진입점 추가. 도메인 전체를 재크롤하되 (1) `content_hash` 미변경 페이지는 LLM·임베딩 비용 0으로 skip → `last_fetched_at`만 갱신 / (2) 변경 페이지는 refine→chunk→embed→Qdrant **diff 동기화**(replace_page_chunks) / (3) 연속 3회 404 페이지 → `REMOVED` + Qdrant 청크 삭제.

## Spec

### `incremental` 진입점

```python
async def run_incremental(ctx, *, job_id: int, domain_id: int) -> None:
    """
    1. start_job(RUNNING)
    2. 기존 pages 중 status NOT IN ('REMOVED', 'DROPPED_PERMANENT') 모두 frontier에 enqueue
       (DROPPED는 incremental에서 다시 시도 — 사이트가 의미있게 바뀌었을 수 있음)
    3. 도메인 root URL도 추가 enqueue (신규 페이지 발견용 BFS)
    4. fetch_page → clean_page → refine_page 체인이 순환 — content_hash 비교는 clean_page에서 분기
    5. 모든 task drain 후 finish_job(SUCCESS)
    """
```

### `clean_page` 분기 (incremental 전용 동작 — full에도 무해)

```python
async def clean_page(ctx, *, job_id: int, page_id: int) -> None:
    page = await s.get(Page, page_id)
    raw = await load_raw(...)
    extraction = extract(raw, page.content_type, blacklist=...)
    new_content_hash = normalize_for_hash(extraction.body_text)

    if page.content_hash and page.content_hash == new_content_hash:
        # 동일 — skip (LLM·임베딩 비용 0)
        page.last_fetched_at = datetime.now(timezone.utc)
        # status는 그대로 유지 (INDEXED 또는 REFINED)
        await s.commit()
        await bump_stats(s, job_id, skipped=1)
        logger.info("clean_skip_unchanged", page_id=page_id, content_hash=new_content_hash[:8])
        return

    # 다름 — refined 본문·헤더 정보 storage/refined/.../page.json 저장 + refine_page enqueue
    await save_cleaned(...)
    page.content_hash = new_content_hash
    page.title = extraction.title
    page.status = "CLEANED"
    await s.commit()
    await ctx["arq"].enqueue_job("refine_page", job_id=job_id, page_id=page_id)
```

### Diff 동기화 — refine_page 후속

`refine_page`가 `is_meaningful=true` + 청크 빌드 완료 후, T3.3의 `replace_page_chunks`를 호출:

```python
async def refine_page(ctx, *, job_id: int, page_id: int) -> None:
    # ... 사전 룰 + OpenAI 호출 (T2.3) ...
    if pre.drop or not refine_result.refined.is_meaningful:
        # is_meaningful=false 전환 → 기존 청크 모두 삭제
        old_chunk_ids = await get_qdrant_point_ids_for_page(s, page_id)
        if old_chunk_ids:
            await QdrantDirectAdapter().delete_by_ids(old_chunk_ids)
            await delete_chunks_pg(s, page_id)
        page.status = "DROPPED"
        page.drop_reason = pre.reason or "not_meaningful"
        await bump_stats(s, job_id, dropped=1)
        return

    # 청크 빌드 + 임베딩 + replace_page_chunks (diff)
    chunks = chunk_page(ChunkInput(...))
    chunk_ids = await upsert_chunks_meta(s, page_id, None, chunks)
    embedded = await embed_to_memory(s, chunk_ids, model=..., job_id=job_id)
    sync = await QdrantDirectAdapter().replace_page_chunks(
        page_id=page_id, embedding_version=settings.embedding_version, new_points=embedded,
    )
    page.status = "INDEXED"
    page.last_indexed_at = datetime.now(timezone.utc)
    await bump_stats(s, job_id, refined=1, indexed=sync.upserted)
```

### Orphan 처리 (`orphan.py`) — `04_incremental_admin.md` §4.4

```python
ORPHAN_404_THRESHOLD = 3       # 연속 3회 404


async def handle_404(s: AsyncSession, page_id: int, job_id: int) -> None:
    """fetch_page에서 http_status=404일 때 호출. error_count++.

    error_count >= 3이면:
      1) qdrant_point_id들을 모아 delete_by_ids
      2) PG chunks DELETE
      3) pages.status = 'REMOVED'
    """


async def handle_domain_deactivation(s: AsyncSession, domain: Domain) -> None:
    """is_active=false로 변경 시 호출 (T1.3 PATCH hook 결선).

    1) Qdrant: delete_by_domain(domain.host) — 컬렉션 전체 도메인 청크 삭제
    2) PG: pages.status='REMOVED' UPDATE all
    3) chunks PG는 cascade로 자동 삭제 (page_id ON DELETE CASCADE 활용 — 직접 DELETE)
    """
```

`fetch_page`에서 404 시 `handle_404` 호출. 이미 `error_count` 컬럼이 `pages`에 있음(`migrations/0002`). 404 외 4xx는 즉시 ERROR (재시도 안 함).

### `incremental` API 엔드포인트

```python
@router.post("/incremental/{domain_id}", response_model=JobOut, status_code=201)
async def trigger_incremental_job(domain_id: int, ...):
    domain = await s.get(Domain, domain_id)
    if domain is None or not domain.is_active:
        raise HTTPException(404)
    job = CrawlJob(domain_id=domain_id, job_type="incremental", status="PENDING",
                   stats={"discovered": 0, ...})
    s.add(job); await s.commit(); await s.refresh(job)
    pool = await get_arq_pool()
    arq_job = await pool.enqueue_job("run_incremental", job_id=job.id, domain_id=domain_id)
    job.arq_job_id = arq_job.job_id
    await s.commit()
    return job
```

### Stats 추가 키

기존 stats JSONB에 `skipped` 카운트 추가 (T2.4에서 정의). incremental에서 의미 있게 사용:
- `discovered`: 새 URL 발견 (frontier에 push된 신규)
- `fetched`: HTTP 200으로 응답 받음
- `skipped`: content_hash 미변경
- `refined`: LLM 호출 후 성공
- `indexed`: Qdrant upsert된 청크 수
- `dropped`: 사전 룰 또는 not_meaningful로 DROPPED
- `errors`: 네트워크/추출/임베딩 실패
- `removed`: orphan 처리로 REMOVED 전환된 페이지 수 (신규 키)

### 테스트

`test_incremental.py` (≥8):
- 도메인의 INDEXED 페이지가 동일 content_hash로 재크롤 → skipped++ + LLM 미호출
- INDEXED 페이지가 변경된 본문으로 재크롤 → refined++ + replace_page_chunks 호출 + indexed 갱신
- 새 URL 발견 → discovered++ + 정상 체인
- DROPPED 페이지가 다시 의미 있는 본문으로 변경 → INDEXED 전환
- INDEXED 페이지가 not_meaningful로 변경 → 기존 chunks 삭제 + DROPPED
- API: `POST /api/jobs/incremental/{id}` → 201 + job 행 생성 + ARQ enqueue
- 비활성 도메인 (`is_active=false`) → 404
- stats.skipped + stats.refined 합계 = 총 처리 페이지 수

`test_orphan.py` (≥6):
- error_count=2 + 404 → error_count=3 + REMOVED + delete_by_ids 호출
- error_count=2 + 200 → error_count=0 (리셋)
- error_count=0 + 첫 404 → error_count=1, REMOVED 안 됨
- 도메인 비활성화 → delete_by_domain 호출 + 모든 페이지 REMOVED
- delete_by_domain 결과 카운트가 stats.removed에 반영
- REMOVED 상태 페이지는 다음 incremental에서 frontier 미진입
