# 크롤러 아키텍처 일반화 리포트 (Generalization Report)

**일시:** 2026-07-11 · **원칙:** 보고된 결함을 개별 사이트 패치로 고치지 않는다. 각 결함을 **누락된 크롤러 능력(capability)**으로 환원하고, 모든 지원 크롤러에서 동일 약점을 탐지한 뒤, **엔진 규칙**으로 일반화하고, 전 사이트 회귀 검증한다. "2개 이상 사이트가 같은 증상 → 엔진이 틀린 것으로 간주."

## Capability 1 — 비콘텐츠 URL 분류 (Navigation/Authentication filtering) ✅ 일반화 완료

| 항목 | 내용 |
|---|---|
| **Root cause** | 비콘텐츠(로그인/회원/인증/유틸) URL 필터가 크롤러마다 **분산·불완전**: (a) `internal_links`는 불완전한 고정 substring 리스트(`/findid`는 있으나 `pw_search`·하이픈 `find-id` 누락), (b) `spider`는 **필터 전무**, (c) sports는 HTML auth-wall만. → **엔진 결함** |
| **일반화된 규칙** | `crawl/url_class.py` `is_non_content_url()` 단일 규칙. **강한 토큰**(login·memberjoin·pwsearch·findid·checkplus…)은 정규화 경로 substring 매칭(compound `memberJoinSelect` 포착), **짧은 토큰**(join·cart…)은 세그먼트-정확 매칭(`border`≠order·`concert`≠cert 오검출 회피). `find-id`→`findid`, `pw_search`→`pwsearch` 정규화. `internal_links`·`spider`가 공통 위임 |
| **Sites affected before** | spobiz, spowell (reported 2개) |
| **Newly discovered** | **ksponco, spoex, edu** (전 사이트 시뮬레이션으로 발견) |
| **영향 규모** | **5개 사이트 / 11 페이지** 오적재 |
| **Sites fixed** | 5개 전부. 기존 11건 Qdrant+PG 정리 + spobiz 라이브 재크롤(인증 0 / 콘텐츠 455 유지) + 전 사이트 재시뮬 **잔여 0** |
| **Remaining exceptions** | 없음 |
| **Site-specific 필요?** | 불필요. 오검출 회피: `facilityFindMember`(시설 수강신청 콘텐츠)를 위해 `findmember` 토큰 제외 |

## Capability 2 — 깊이 전략 (Depth strategy) ✅ 엔진은 이미 정상, 데이터 드리프트 교정

| 항목 | 내용 |
|---|---|
| **Root cause** | 보고: www.kspo.or.kr가 게시판 상세(depth 3+) 미도달. 조사: 엔진 기본값은 **이미 10**(`settings.spider_max_depth=10`, model `server_default="10"`). www.kspo.or.kr만 값이 **2로 드리프트** |
| **일반화된 규칙** | 엔진 기본 max_depth=10 (신규 도메인 자동 상속) — 이미 존재 |
| **Sites affected before** | www.kspo.or.kr (유일) |
| **Newly discovered** | 없음 (전 20개 도메인 감사 → 전부 10) |
| **Sites fixed** | www.kspo.or.kr → 10 정렬 |
| **Site-specific 필요?** | 불필요 (엔진 규칙이 이미 옳음, 1건 데이터 교정) |

## Capability 3 — 상세페이지 발견 / Content-Unit URL 생성 (Detail discovery) ⚠️ 사이트별 불가피

| 항목 | 내용 |
|---|---|
| **Root cause** | `internal_links._add_board_view_links`가 `list.do→view.do?nttId=` 생성. eGov 표준 게시판(nttId)엔 정확하나, **sports.re.kr은 `con_seq`+`fnBoardContentView`**, **ksponco는 `board.es` CMS**로 상세 URL 규약이 다름 |
| **일반화된 부분** | eGov 표준 nttId 상세 발견은 엔진이 정확히 처리 (dvoucher·svoucher·cleansports·spobiz·soma 모두 상세 수집됨) |
| **Sites needing site-specific** | **sports.re.kr** (전용 크롤러 존재 — 738 docs), **ksponco FAQ** (board.es 어댑터 필요) |
| **왜 불가피** | 상세 URL 파라미터 규약은 **CMS 템플릿 고유**. 함수명 `fnBoardContentView`가 파라미터 규약을 인코딩하지 않아 범용 추론 불가. sports.re.kr은 **전용 크롤러가 올바른 site-specific 해법** |
| **Remaining exceptions** | ksponco FAQ 상세(board.es) 미발견 — board.es 어댑터 추가 시 해결. sports.re.kr 전용 크롤러의 Qdrant 연동 미완 |

## Capability 4 — JavaScript 라우팅 / API 발견 (JS routing / API discovery) ⚠️ 사이트별 불가피

| 항목 | 내용 |
|---|---|
| **Root cause** | kboat/kcycle 핵심 경주데이터(일정·결과·선수), nfa가 **JS/XHR/API 로딩** — 정적 HTML 링크에 없음. 정적 링크 발견으로 도달 불가 |
| **일반화된 부분** | SPA 렌더링(Playwright, 이미 도입)으로 BROWSER 프로파일 사이트의 렌더된 HTML 수집 (cleansports/spoex 복구) |
| **Remaining exceptions** | XHR/API 엔드포인트 뒤의 경주데이터는 **사이트별 API 어댑터** 필요. nfa는 세션벽 |
| **왜 불가피** | API 엔드포인트·파라미터는 사이트 고유. 범용 크롤러가 임의 XHR API를 신뢰성 있게 발견 불가 |

## Capability 5 · 6 — 결함 아님 / 범위 결정

- **cleansports "없는 경로"** (SPA URL): 데이터는 유효(렌더 200 적재). URL이 SPA 내부 라우트라 브라우저 직접접속엔 라우터 필요 — **크롤 결함 아닌 내비게이션 표시 특성**.
- **spoex video/77, css 훈련영상** (Media/Content-Unit): **페이지는 이미 수집**(전시소개·갤러리). **영상 콘텐츠(재생/자막)는 WS7 범위**(`youtube_caption.py`가 국민체력100용 존재). 일반 영상 자막 확장은 **엔진 결함이 아닌 프로젝트 범위 결정**.
