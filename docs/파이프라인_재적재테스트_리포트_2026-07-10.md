## 4. 발견된 이슈 (근본원인 규명)

**① 플래그십 `www.kspo.or.kr`가 처음에 크롤 안 됨 → 규명·해소**
- 원인: job_guard 수정 **이전에 생긴 유령 RUNNING job 6개**(2026-07-05)가 남아, `monthly_full_all`의 "활성 job 있으면 skip" 규칙에 걸려 제외됨.
- 조치: 1시간+ 정체 job 정리(→FAILED) 후 재크롤. **메인 파이프라인엔 sports 크롤러와 달리 stale-job 자동정리가 없음** → 개선 필요 항목.

**② 플래그십이 27개만 적재된 이유 = 설정 상한 (버그 아님)**
- `www.kspo.or.kr`는 **max_pages=30** 설정 → 정확히 30개 처리 후 중단, **1,110개는 발견(DISCOVERED)했으나 상한으로 미처리**.
- 즉 **링크 탐색은 완벽히 작동**(1,110개 발견), 단지 도메인 설정이 30으로 낮음. 다른 도메인은 20000. → 운영 시 max_pages 상향 필요.

**③ ~8개 도메인이 root만 적재 = root fetch 실패**
- `dvoucher/soma/ksponco/parktel/ecolian/sportsvalue/kspo.or.kr(apex)/spoex`: root가 **ERROR**(http_status=NULL = SSL/연결 실패). httpx가 실패한 곳을 curl은 되는 경우도 있어 **fetcher의 TLS/인증서 처리** 조사 필요.
- 특히 `kspo.or.kr`는 **apex 도메인이 HTTPS 실패**(인증서는 www용) + `www.kspo.or.kr`와 **중복 등록**. → apex 행 정리 권장.
- `edu/spowell`: root가 **DROPPED**(얇은 JS 홈) — 브라우저 렌더링 필요(WS7 영역).

**④ 기존 통계 롤업 결함(무관, 기존 이슈)**: job stats의 `drop_reasons`가 전부 0으로 집계 — 실제 DROPPED 392건과 불일치. 이번 수정 범위 밖의 기존 버그(감사에서 이미 지적).

## 6. 결론

- **핵심 질문 "초기화 후 온전히 재적재되는가?" → 예, 검증됨.** 0에서 2,048 벡터까지 전 경로가 실시간으로 정상 작동했고, RAG 응답까지 확인.
- **파이프라인 자체 버그는 없음.** 커버리지 편차는 전부 (a) 도메인 설정(max_pages=30), (b) root fetch 실패(SSL/JS), (c) 수정 이전 유령 job 잔재 — **설정/데이터 이슈이지 파이프라인 결함이 아님**.
- **부수 성과**: job_guard 수정이 실환경에서 유령 job 0건으로 검증됨.
