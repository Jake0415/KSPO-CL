## 1. 크롤러 작동 방식

### 파이프라인 흐름

```
Domain 등록 (host, scheme, max_depth, max_pages)
    │
    ▼
[BFS Frontier] ── seed URL (root) push
    │
    ▼ (루프)
Dequeue URL → robots.txt 체크 → Rate Limit 대기
    │
    ▼
Fetch (httpx, HTTP/2, User-Agent, 5회 재시도, 10MB 상한)
    │
    ▼
Clean (Trafilatura + readability, 셀렉터 블랙리스트, EUC-KR/CP949 인코딩 처리)
    │
    ▼
Extract Links → 내부 링크 → Frontier enqueue (same-host BFS)
    │            → 첨부파일 → 메타만 기록 (다운로드 안 함)
    ▼
Refine (LLM structured output → 본문/요약/키워드 추출)
    │
    ▼
Chunk (800토큰 기준 분할, 컨텍스트 헤더 포함)
    │
    ▼
Embed (text-embedding-3-large, 3072차원)
    │
    ▼
Qdrant Direct Upsert (page_content + metadata + tags)
```

### 핵심 모듈

| 모듈 | 역할 |
|------|------|
| `crawl/fetcher.py` | httpx 비동기 HTTP, HTTP/2, 5회 재시도 (5xx/429), 10MB 상한 |
| `crawl/frontier.py` | Redis BFS 큐 (FIFO, 중복 차단, inflight 추적) |
| `crawl/robots.py` | robots.txt 파싱 + 캐싱 |
| `crawl/rate_limit.py` | 호스트별 RPS 제한 (기본 1.5 req/s) |
| `crawl/internal_links.py` | 같은 호스트 내부 링크 추출 (same-host BFS) |
| `clean/extractor.py` | Trafilatura → readability → heuristic (3단 폴백) |
| `clean/encoding.py` | EUC-KR/CP949 → UTF-8 디코딩 |
| `refine/refiner.py` | LLM 정제 (OpenAI/Gemini 팩토리) |
| `chunk/chunker.py` | 2단 청킹 (>800토큰 분할, 그 외 단일) |
| `embed/embedder.py` | text-embedding-3-large 임베딩 |
| `qdrant/adapter.py` | Qdrant Direct upsert + 필터 삭제 |

### 크롤 정책

- **same-host BFS**: 등록된 Domain의 호스트 내에서만 순회 (cross-host 차단)
- **depth 제한**: Domain.max_depth (기본 10)
- **pages 제한**: Domain.max_pages (기본 20,000)
- **rate limit**: Domain.rate_limit_rps (기본 1.5)
- **incremental**: content_hash 비교로 미변경 페이지 skip
- **게시판**: is_board=True 도메인은 매일 04:00 KST 갱신, 3개월 freshness 필터
- **첨부 파일**: 메타(URL/파일명/MIME)만 기록, 다운로드·OCR 없음 (텍스트만)
